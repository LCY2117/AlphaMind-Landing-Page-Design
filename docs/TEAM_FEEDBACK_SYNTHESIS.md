# AlphaMind 团队建议整理与落地计划

整理日期：2026-05-26

来源材料：本地会议纪要、微信群聊建议整理与 Gemini 二次总结。

## 一句话结论

团队本轮建议的核心不是“再堆几个页面”，而是把 AlphaMind 从模块展示升级为一个路演能讲通的智能投顾闭环：

**用户进入系统 -> 系统识别用户画像和关注资产 -> 首页给出个性化标的研究入口 -> 风险画像动态校准 -> 资产透视解释标的状态 -> AI 投顾输出 2-3 个决策分支和风险预警。**

当前版本已经有较好的视觉基础、风险测试、资产透视和 AI 对话雏形，但还缺少“用户画像驱动投顾建议”的主线，以及国内资产场景下的演示可信度。

## 长任务执行规则

### 1. 缺 API Key 不进入阻塞队列

后续长任务中，如果某个功能缺少第三方 API Key，不把它放入阻塞队列，也不停止开发。统一改走演示数据替代流程：

1. **全网调研演示数据**：围绕国内资产、黄金、指数、行业新闻、历史走势和典型风险事件，调研足够多的公开信息，形成有广度和深度的演示数据素材。
2. **接入本地演示数据**：将调研结果结构化为本地 mock/demo provider，接入首页推荐、资产透视、风险预警、投顾建议和持仓监控等模块。

验收时允许使用演示数据，但界面必须明确标注“演示数据 / 样例数据 / 情景推演”，不能伪装成实时行情或真实账户数据。

### 2. 真实登录体系不做

真实微信扫码登录、真实短信验证码、真实账户密码体系不纳入当前路演版本范围。

当前产品定位为进入系统后默认拥有一个演示账户，因此只需要保留或优化本地演示账户体验：

- 一进入系统即可体验核心功能。
- 登录状态可作为“演示身份 / 本地账户”存在。
- 不等待微信开放平台、短信服务商、后端账号系统或审核流程。

### 3. 预测只做合理情景推演

“预测涨幅”不要求实现精准预测模型。当前版本只需要做到：

- 基于历史曲线、新闻线索、波动状态和用户画像生成合理的预测区间。
- 给出 AI 自认为的原因，例如趋势动量、风险偏好、新闻情绪、资产属性。
- 展示 2-3 个情景分支，而不是承诺单一确定结果。

推荐文案使用“AI 预测区间”“情景推演”“研究视角”“风险收益分支”，避免“精准预测”“必涨”“保证收益”等表达。

### 4. 用户画像是推荐主线

首页展示资产、投顾建议模板和推荐解释，都应围绕“用户画像记忆证据”组织。

短期需要实现轻量用户画像能力，不要求后端复杂系统，但至少包含：

- 风险测试结果。
- 最近关注资产。
- 对话中反复出现的资产或主题。
- 简单情绪/风险偏好标签。
- 推荐理由中引用这些画像证据。

如果推荐标的、首页展示顺序或投顾模板没有团队进一步指定，由系统根据用户画像和路演叙事自行选择默认方案。

### 5. 云端与 GitHub 可用于验证

必要时可以使用 GitHub 同步和云端部署能力进行测试与验证。执行时仍需遵守：

- 不提交 `.env.local`、真实 API Key、token 或其他秘密。
- 部署前先完成本地构建。
- 云端变更后进行基本 smoke test。
- 生产环境问题优先修复前端可见体验，不做高风险破坏性操作。

## 团队共识

### 1. 投顾建议的定位要改清楚

投顾建议的核心应是“预测决策”和“决策辅助”，不是直接推荐用户买某只股票。

建议表述方向：

- 不说“建议买入某股票”。
- 改为“基于当前画像与市场信号，给出可能决策分支、收益风险情景和注意事项”。
- 所有结论都保留“研究辅助，不构成投资建议”的边界。

### 2. 项目要本土化

当前资产透视中 TSLA、NVDA、AAPL 等美股展示不够贴合团队路演语境。团队希望展示国内用户熟悉的资产，例如：

- 贵州茅台
- 黄金或黄金 ETF
- 宁德时代
- 招商银行
- 沪深 300 / 中证 500 等指数型资产

实现上采用演示数据优先：

- 路演版本先通过公开信息调研构建国内资产演示数据，明确标注“演示数据/样例数据”。
- 后续真实版本再接入 A 股、基金、黄金、指数等数据源。

### 3. 首页要承担“个性化推荐入口”

首页不应只展示品牌和科技视觉，还应成为用户打开系统后的第一层投顾入口。

团队提出首页需要：

- 推荐 3 支或 3 类资产。
- 展示涨幅情况。
- 展示 14 天起伏趋势图。
- 展示预测涨幅或预测区间。
- 展示与用户画像的契合描述。
- 增加股票搜索功能。

产品上建议将“推荐股票”弱化为“个性化研究候选”，避免过度承诺。

### 4. 用户画像要和投顾建议联动

风险测试不能只是孤立模块。团队希望风险测评结果影响首页推荐、资产透视风险提示和 AI 投顾建议。

关键需求：

- 用户完成风险测评后，不只是展示风险分数。
- 在推荐资产下方展示风险预警仪表盘。
- 根据用户行为动态修正画像，例如：
  - 用户连续 3 次忽略高置信度建议。
  - 用户多次关注同一资产。
  - 用户在对话中表达焦虑、兴奋、恐慌等情绪。

路演版本可以先用本地状态模拟这些信号，不必等真实后端。

### 5. AI 对话需要图文和图表化

当前对话如果全部是文字，会显得单调。团队希望 AI 对话能够输出更像投顾报告的结构化内容。

建议 AI 回复至少支持以下卡片：

- 投顾建议卡片
- 风险预警卡片
- 资产对比卡片
- 迷你趋势图
- 决策分支表
- 用户画像引用说明

同时需要保留历史对话记录，并展示聊天时间。

### 6. 深度思考提示词泄露必须修

团队明确提到：深度思考过程中不能泄露系统提示词，例如“你是一名专业的 xxx”“不要提及比赛”等内容。

这是路演版本的高优先级问题。原因：

- 会直接破坏专业感。
- 会让评委觉得系统只是提示词包装。
- 可能暴露内部实现边界。

处理原则：

- 前端只展示模型返回的可公开分析摘要。
- 后端要过滤疑似系统提示、开发提示、比赛提示、角色提示泄露文本。
- 深度思考区域可以展示“分析步骤摘要”，但不展示真实内部链路或系统提示词。

### 7. 风险测试题库要更自然

团队希望风险测试：

- 一次只问 5 个问题。
- 题库设置 15 个问题。
- 每天轮换抽取。
- 最后一个问题偏情绪化、非专业化，例如“今天心情怎么样？”

当前项目已经是 5 题流程，但题库轮换和最后一题情绪化还需要调整。

### 8. 补充持仓动态监控和收益走势预测

团队从说明书中补充了一个核心功能：

- 支持按账户、资产类型、时间范围筛选持仓数据。
- 展示收益走势。
- 展示风险评估。
- 形成持仓动态监控能力。

这个功能适合做成“路演演示型模块”，短期可用本地模拟数据展示完整交互。

## 路演版本优先级

### P0：必须完成

这些内容直接影响评委第一印象和演示可信度。

1. 修复深度思考提示词泄露。
2. 首页新增“个性化研究候选”区域，展示 3 个国内资产。
3. 首页新增股票搜索入口，可跳转资产透视。
4. 资产透视默认资产改为国内演示标的。
5. AI 对话增加结构化投顾建议卡片，不再只是大段文字。
6. 对话历史展示时间戳。
7. 风险测试最后一题改为情绪问题。

### P1：强烈建议完成

这些内容可以显著增强“智能投顾闭环”的叙事。

1. 风险画像结果影响首页推荐文案。
2. 推荐资产下方增加风险预警仪表盘。
3. 投顾建议输出固定模板：
   - 用户画像摘要
   - 关注资产证据
   - 当前市场信号
   - 2-3 个决策分支
   - 正面因素
   - 风险压力
   - 边界声明
4. 用户多次关注某资产后，在首页动态问候中体现。
5. 增加“理财科普 / AI 主动提醒”小模块。

### P2：可延后

这些更偏真实产品化，当前路演版本明确不做或不阻塞。

1. 真实账户密码体系。
2. 真实微信扫码登录。
3. 真实短信验证码。
4. 真实持仓接入。
5. 真实 A 股全量行情源。
6. 用户行为长期画像后端。
7. 真正可验证的收益预测模型。

## 建议的产品主线

### 首屏故事

用户进入 AlphaMind，系统显示：

- 动态问候语：例如“欢迎回来，最近您持续关注白酒和黄金防御资产。”
- 用户画像摘要：稳健型 / 进取型 / 保守型。
- 3 个个性化研究候选：
  - 贵州茅台：消费龙头，适合稳健型长期观察。
  - 黄金 ETF：防御资产，适合波动期平衡组合。
  - 宁德时代：成长弹性较高，适合进取型用户小仓位研究。

每个候选展示：

- 今日涨跌幅
- 14 天趋势迷你图
- AI 预测区间
- 与用户画像契合原因
- 风险预警等级
- “查看资产透视”按钮

### 风险画像故事

用户完成 5 题测试后，看板不只是给分，而是告诉用户：

- 你的风险偏好是什么。
- 哪类资产更匹配。
- 哪些资产虽然热门，但不适合当前画像。
- 哪些行为信号正在改变你的画像。

### 投顾建议故事

AI 不直接告诉用户买什么，而是输出：

```text
基于您最近反复关注贵州茅台、风险画像为稳健型、近期市场波动加大，AlphaMind 给出三种决策分支：

方案 A：继续观察
可能结果：错过短期反弹，但降低追高风险。

方案 B：小仓位分批研究
可能结果：参与潜在修复，同时控制回撤。

方案 C：等待风险释放
可能结果：更保守，但机会成本较高。

正面因素：品牌壁垒、现金流、长期分红能力。
风险压力：估值、消费复苏节奏、市场情绪波动。
```

## 开发任务拆分

### 任务 1：首页推荐研究候选

目标：

- 首页增加 3 个国内资产推荐卡。
- 每张卡包含涨幅、14 天趋势、预测区间、画像契合说明。
- 点击可进入资产透视。

验收：

- 首页移动端和桌面端都能完整展示推荐区。
- 3 个资产不再是 TSLA/NVDA/AAPL。
- 卡片文案不出现“稳赚”“必涨”等承诺。

### 任务 2：资产透视本土化

目标：

- 默认资产改为国内演示资产。
- 样例数据替换为贵州茅台、黄金 ETF、宁德时代等。
- 搜索提示改为国内代码/名称。

验收：

- 资产透视页面首屏不再默认显示 TSLA。
- 新闻、催化因子、结论文案符合国内资产语境。
- 未接真实行情时明确标注演示数据。

### 任务 3：投顾建议模板化

目标：

- AI 对话中出现“投顾建议卡片”。
- 卡片展示用户画像、关注证据、决策分支、正反因素。
- 普通问题仍可正常文本回答。

验收：

- 输入“帮我分析一下茅台”后，出现结构化建议卡片。
- 卡片支持跳转资产透视。
- 不泄露系统提示词。

### 任务 4：风险画像联动

目标：

- 风险测试结果写入本地画像状态。
- 首页推荐和投顾建议读取画像状态。
- 推荐卡显示风险预警仪表盘。

验收：

- 完成风险测试后，首页推荐文案发生变化。
- 同一资产在保守型/进取型画像下显示不同风险提示。
- 风险提示不是弹窗强阻断。

### 任务 5：风险测试题库轮换

目标：

- 建立 15 题题库。
- 每天抽取 5 题。
- 最后一题固定来自情绪题池。

验收：

- 同一天刷新页面题目稳定。
- 第二天题目组合可变化。
- 最后一题为情绪/状态问题。

### 任务 6：对话历史与时间显示

目标：

- 每条消息展示时间。
- 历史会话列表显示最近更新时间。
- 保持现有 localStorage 历史记录。

验收：

- 新消息能看到发送时间。
- 切换会话后时间仍存在。

### 任务 7：持仓动态监控演示模块

目标：

- 新增或嵌入“持仓动态监控”卡片。
- 支持账户、资产类型、时间范围筛选。
- 展示收益走势和风险评分。

验收：

- 不依赖真实账户也可演示完整流程。
- 明确标注为本地演示持仓。
- 图表和筛选项在移动端不溢出。

## 风险与边界

### 不能过度承诺预测能力

团队提到“预测涨幅”“预测决策”，但产品文案应避免承诺准确预测。

建议统一使用：

- AI 预测区间
- 情景推演
- 研究候选
- 风险收益分支
- 辅助判断

避免使用：

- 必涨
- 必买
- 稳赚
- 准确预测
- 保证收益

### 国内真实行情缺失时走演示数据

如果没有国内行情、新闻和财务数据 API，不进入阻塞队列。长任务应先调研公开信息，形成本地演示数据并接入页面。路演版本先强调“系统能力闭环”，但界面必须标明数据状态。

### 真实登录体系明确不做

真实微信扫码登录、真实短信验证码和真实账户密码体系不属于当前实现范围。项目默认使用演示账户进入，不在这些事项上等待或阻塞。

## 推荐实施顺序

1. 修复提示词泄露与深度思考展示。
2. 首页增加 3 个国内资产推荐卡和搜索入口。
3. 资产透视替换为国内演示资产。
4. AI 对话增加投顾建议结构化卡片。
5. 风险画像联动首页推荐和风险预警。
6. 风险题库改为每日轮换。
7. 增加持仓动态监控演示模块。
8. 做移动端和路演屏幕尺寸检查。

## 路演讲法建议

可以这样讲 AlphaMind：

> AlphaMind 不是简单地给用户推荐股票，而是先理解用户的风险承受能力和行为偏好，再结合资产行情、新闻情绪与 AI 推演，给出多种决策分支和风险预警。系统的目标是帮助用户理解“为什么这样判断”和“不同选择会带来什么后果”，而不是替用户做确定性交易决策。

这套表述比“AI 推荐三只股票”更稳，也更符合投顾合规边界。
