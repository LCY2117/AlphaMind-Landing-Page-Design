## 总目标

将 AlphaMind 从“功能模块展示型 Demo”升级为“路演可讲通的智能投顾闭环”：

```text
默认演示账户
  -> 轻量用户画像
  -> 首页个性化研究候选
  -> 风险画像动态校准
  -> 国内资产透视
  -> AI 投顾建议卡片
  -> 风险预警与情景推演
  -> 持仓监控演示视图
```

最终呈现重点不是“AI 直接荐股”，而是“AI 根据用户画像、资产信号和风险边界，给出可解释的决策辅助”。

## 非目标

本轮长任务不做以下事项：

- 不做真实微信扫码登录。
- 不做真实短信验证码。
- 不做真实账户密码体系。
- 不做真实券商账户或银行账户绑定。
- 不启用真实交易、自动下单或任何 live trading。
- 不承诺精准预测收益或涨幅。
- 不把真实 API Key、token、券商凭证、SSH key 写入仓库。
- 不因为缺少 API Key 而停止任务。
- 不重写整个项目架构。

## 总执行规则

### 1. 缺 API Key 不阻塞

如果遇到第三方 API Key 缺失，不写入阻塞队列，不等待用户申请，不中断长任务。

统一执行替代流程：

1. 全网调研公开资料，收集国内资产、黄金、指数、行业事件、新闻线索、历史趋势和典型风险因素。
2. 将资料整理为结构化演示数据。
3. 接入本地 demo/mock provider。
4. 在界面中明确标注“演示数据 / 样例数据 / 情景推演”。

验收重点是演示数据的广度、深度、可信度和产品闭环，不要求实时行情。

### 2. 用户画像是主线

所有推荐、投顾建议、风险预警和首页展示都必须尽量引用用户画像证据。

轻量画像至少包括：

- 当前风险测试结果。
- 最近关注资产。
- 对话中反复出现的资产或主题。
- 简单情绪状态或风险偏好标签。
- 推荐理由中的画像证据说明。

短期允许全部保存在浏览器本地状态或 localStorage。

### 3. 预测是情景推演

“预测涨幅”统一实现为合理的 AI 情景推演：

- 基于历史曲线、新闻线索、波动特征、资产属性和用户画像。
- 输出预测区间或分支概率。
- 给出 AI 自认为的原因。
- 不承诺准确预测、不承诺收益。

推荐术语：

- AI 预测区间
- 情景推演
- 风险收益分支
- 研究候选
- 辅助判断

禁止术语：

- 必涨
- 必买
- 稳赚
- 精准预测
- 保证收益

### 4. 真实登录体系不做

项目默认用户进入后拥有一个演示账户。后续优化只围绕“演示身份 / 本地账户”体验展开。

如果代码中已有模拟微信或手机号登录，可以保留；但不得把真实微信开放平台、短信服务、真实账户体系作为本轮任务目标。

### 5. 可使用 GitHub 与云端验证

用户已允许必要时使用 GitHub 和云端环境测试。执行时仍需遵守：

- 本地构建通过后再考虑云端同步。
- 不提交 `.env.local` 或任何秘密。
- 云端变更后做基本 smoke test。
- 不做破坏性部署、强制推送、清库、删库、真实交易配置。

## 四锚点

每次启动、恢复、进入新阶段、完成验证或准备停止前，都必须检查：

1. **PLAN**：本文件 `docs/ALPHAMIND_ROADSHOW_LONG_TASK_PLAN.md`
2. **STATE**：`docs/LONG_TASK_STATE.md`
3. **BLOCKERS**：`docs/LONG_TASK_BLOCKERS.md`
4. **GIT**：当前分支、HEAD、dirty files、是否允许 checkpoint commit

如果未来用户授权使用 sub-agent/parallel agent，必须在 `docs/LONG_TASK_STATE.md` 记录每个 agent 的任务范围、写入文件、状态和整合结果。

## 阻塞队列规则

### 不进入阻塞队列

以下情况不应阻塞长任务：

- 缺少国内行情 API Key。
- 缺少新闻 API Key。
- 缺少财务数据 API Key。
- 缺少真实持仓 API。
- 缺少 A 股全量数据源。
- 未确定最终推荐标的。
- 未确定最终投顾话术。

这些情况统一由 Codex 使用演示数据、合理默认方案和本地 mock 继续推进。

### 进入阻塞队列

以下情况必须写入 `docs/LONG_TASK_BLOCKERS.md`，并继续做其他不依赖它的工作：

- 真实交易、下单、券商账户绑定或 live trading 激活。
- 需要用户创建、查看、复制、旋转或提供秘密 API Key/token。
- 需要微信/QQ/SSO 扫码。
- 需要短信、邮箱、手机验证码。
- 需要实名、人脸、学校或公司认证。
- 需要付费、开通服务、绑定银行卡或购买额度。
- 需要接受法律条款、隐私协议或高风险权限。
- 需要用户明确批准的破坏性部署或数据删除。

## 里程碑与验收

### P0：路演可信度与主线闭环

目标：让评委第一眼看懂 AlphaMind 的智能投顾闭环，并消除最影响专业感的问题。

任务：

- [ ] 修复深度思考/推理展示中的提示词泄露。
- [ ] 建立轻量用户画像服务或本地画像状态。
- [ ] 首页新增 3 个国内资产“个性化研究候选”卡片。
- [ ] 首页新增资产搜索入口，可跳转资产透视。
- [ ] 资产透视默认切换为国内演示资产。
- [ ] AI 对话增加结构化投顾建议卡片。
- [ ] 对话消息展示时间，历史会话展示更新时间。
- [ ] 风险测试最后一题改为情绪/状态问题。

验收：

- 首页不再只是品牌介绍，而能展示用户画像驱动的研究候选。
- 默认资产不再是 TSLA/NVDA/AAPL。
- 输入“帮我分析一下茅台”一类问题时，有结构化建议卡片。
- 深度思考区域不出现系统提示词、内部开发提示或比赛提示。
- 所有预测/推荐文案都保持辅助研究边界。
- `npm run build` 通过。

### P1：画像联动与路演表现力

目标：让首页、风险测试、资产透视、AI 对话互相引用，形成产品故事。

任务：

- [ ] 风险画像结果影响首页推荐文案。
- [ ] 推荐资产下方增加风险预警仪表盘。
- [ ] 投顾建议卡片固定输出模板：
  - 用户画像摘要
  - 画像记忆证据
  - 当前资产信号
  - 2-3 个决策分支
  - 正面因素
  - 风险压力
  - 边界声明
- [ ] 用户多次关注某资产后，首页动态问候或推荐理由发生变化。
- [ ] 增加“理财科普 / AI 主动提醒”轻量模块。
- [ ] 风险测试改为 15 题题库，每天稳定抽取 5 题，最后一题来自情绪题池。

验收：

- 完成风险测试后，首页推荐理由发生可见变化。
- 同一资产在不同风险画像下显示不同风险提示。
- AI 建议不是纯文本，而是图文/表格/卡片化输出。
- 当用户多次关注某资产，系统能体现“记忆证据”。

### P2：持仓监控与演示数据深度

目标：补足说明书中的核心功能展示，让项目显得更完整。

任务：

- [ ] 新增或嵌入持仓动态监控演示模块。
- [ ] 支持账户、资产类型、时间范围筛选。
- [ ] 展示收益走势、风险评分、波动提醒。
- [ ] 为国内资产补充更丰富的演示新闻、历史走势、风险事件和结论素材。
- [ ] 做桌面端、移动端、路演屏幕尺寸 smoke check。

验收：

- 持仓监控不依赖真实账户也能演示完整流程。
- 图表和筛选项在移动端不横向溢出。
- 页面明确标注本地演示持仓或样例数据。
- 演示数据看起来有足够广度和深度，不像三行硬编码文案。

## 演示数据调研要求

长任务中如果需要填充演示数据，调研应覆盖：

- 资产基本属性：行业、资产类型、风险特征。
- 近期典型新闻或市场事件。
- 历史走势的合理样例曲线。
- 正面因素和风险压力。
- 适配不同用户画像的解释。
- 可用于投顾建议卡片的决策分支。

调研结果不需要逐条做学术引用，但不能编造重大事实。若无法确定事实，应写成“样例事件 / 情景假设 / 演示数据”。

## Git 规则

- 启动长任务前记录分支、HEAD、dirty files。
- 不提交 `.env.local`、真实 key、token 或生成的大包。
- 如果用户授权 checkpoint commits，可按 P0/P1/P2 做阶段性提交。
- 如果用户未授权提交，只记录状态和 diff，不自动提交。
- 不使用 `git reset --hard`、强推、删除分支等破坏性操作，除非用户明确要求。
